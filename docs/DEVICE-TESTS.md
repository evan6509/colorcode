# Device verification still required

These are pending checks, not recorded passes. No APK was installed during the sandbox run.

1. On an Android 8+ phone, open Make. Test empty text, emoji, Greek/Japanese, embedded controls and the capacity limit. Save a PNG using a document provider. Restart the app and import that PNG. Save decoded bytes and compare them to the original file outside the app.
2. Repeat with arbitrary binary files of 599, 1591 and 3484 bytes in the corresponding grids. Try one byte too many and a file larger than the global maximum. Confirm clear errors and no replacement of a previous successful preview by invalid data.
3. Share payload A, retain its actual granted URI in a recipient, then create/share payload B. Reopen both: A must still contain only A, B only B. Hold A's file descriptor open through later shares and expiry cleanup; it must continue to read A. Confirm expired URIs fail and live shares survive cleanup. Try literal/encoded traversal, alternative authorities, query/fragment variants, legacy static URIs and write modes against the actual provider; none may expose unrelated files or modify PNGs. Also try a provider denying access, a canceled picker, missing picker/share apps and a full storage device. The JVM regressions do not verify Android grant enforcement.
4. Repeatedly rotate/recreate/background the Activity before, during and immediately after generation, binary import and image decode. Let work finish while no activity is resumed, then return; each result/error must be delivered once, controls must recover and a restored older preview must not replace a new code or hide a decode error. Rotate in a document picker and finish a pending export after recreation. For camera decode, rotate on both success and failure: the capture must remain until successful delivery, and **Retry last photo** must use the same bytes after failure. Force process death separately: retained work is not durable; retry manually from restored input (or reopen an imported document).
5. Deny camera permission; import a PNG successfully. Grant permission and exercise camera cancel, capture, retry, timeout, camera-in-use/disconnection and pause/resume. With a Camera2 callback harness, time out request A, start B, then deliver A's JPEG and metadata before/after B's metadata. Only B's matching timestamp may finish B. Exercise both JPEG-before-metadata and metadata-before-JPEG orders, duplicates, missing timestamps and stale failures/timeouts. Verify portrait/landscape preview orientation and saved JPEG orientation on devices with different sensor orientations. Verify there is no camera leak or capture from a stale session. JVM matcher tests cover the ordering logic, not the Camera2/HAL timestamp contract.
6. Photograph displayed color codes at recorded module pitch, distance, angle, illumination, focus/exposure and device model. Test each payload/grid and record failures as well as successes. The current marker checks are strict. No result should appear unless framing, RS and CRC pass.
7. If printing, record paper/printer/ink/profile, physical module pitch, lighting and capture device. Test actual printed samples rather than extrapolating from PNG or synthetic perspective tests.
8. For a real optical density comparison, generate standard QR-L v10/v18/v28 using an independent validated QR encoder, with the same physical area and quiet-zone allocation. Compare payload and failure rates across devices and conditions. Also compare ECC strengths explicitly; the current digital comparison does not equalize optical robustness.

Do not interpret the existing synthetic JPEG, blur, projective or color-cast tests as these device/print results.
